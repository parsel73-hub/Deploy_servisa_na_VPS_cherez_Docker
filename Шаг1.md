# Шаг 1. Сервис приложения (код)

## Какую роль играет этот шаг в проекте

Это фундамент всего проекта. Здесь создаётся сам Python-сервис (FastAPI), который впоследствии будет:
- упакован в Docker-образ (Шаг 2);
- запущен через Docker Compose (Шаг 3);
- развёрнут на VPS reg.ru и доступен по публичной ссылке (Шаг 7).

Без работающего сервиса все последующие шаги (контейнеризация, деплой, проверка) не имеют смысла — контейнеризировать и деплоить нужно уже существующее приложение. Роль Шага 1 — получить **работоспособное приложение с эндпоинтами**, которые удовлетворяют критериям задания: минимум один endpoint должен успешно отвечать по сети.

Выбран сервис **Number / Random / Fact API** — простой, без внешних зависимостей и БД, что делает его надёжным для демонстрации деплоя.

## Что сделано

Создана папка `app/` (модульная структура проекта) с двумя файлами:

- `app/main.py` — код сервиса на FastAPI.
- `app/requirements.txt` — зависимости (`fastapi`, `uvicorn`).

### Эндпоинты сервиса

| Метод | Путь | Назначение |
|-------|------|------------|
| GET | `/` | Приветствие + список эндпоинтов |
| GET | `/health` | Health-check (главная точка проверки из задания) |
| GET | `/api/random?min=1&max=100` | Случайное число из диапазона |
| GET | `/api/fact` | Случайный факт из встроенного списка |
| GET | `/api/dice?sides=6&count=3` | Бросок кубиков |

## Критерий готовности шага

Сервис запускается локально, и все эндпоинты отвечают корректным JSON.

---

## Как проверить работоспособность самостоятельно

### Вариант A — через виртуальное окружение проекта (Python + uvicorn)

1. Убедись, что зависимости установлены:
   ```powershell
   .\.venv\Scripts\pip.exe install -r app\requirements.txt
   ```
   > Если pip падает по таймауту к pypi.org, повтори с увеличенным таймаутом:
   > `.\.venv\Scripts\pip.exe install --default-timeout=120 --retries=5 -r app\requirements.txt`

2. Запусти сервер из корня проекта (флаг `--app-dir app` указывает, где лежит `main.py`):
   ```powershell
   .\.venv\Scripts\python.exe -m uvicorn --app-dir app main:app --port 8050
   ```

3. В отдельном терминале проверь эндпоинты:
   ```powershell
   curl.exe -s http://localhost:8050/health
   curl.exe -s http://localhost:8050/api/fact
   curl.exe -s "http://localhost:8050/api/random?min=5&max=10"
   curl.exe -s "http://localhost:8050/api/dice?sides=6&count=3"
   ```

4. Останови сервер: `Ctrl+C`.

### Вариант B — через интерактивную документацию FastAPI

После запуска из варианта A открой в браузере:
- http://localhost:8050/docs — Swagger UI, где можно кликами протестировать каждый эндпоинт;
- http://localhost:8050/redoc — альтернативная документация.

### Ожидаемые ответы (пример)

```json
GET /health            -> {"status":"ok"}
GET /api/fact          -> {"fact":"Человеческий мозг на ~73% состоит из воды."}
GET /api/random?...    -> {"min":5,"max":10,"random":6}
GET /api/dice?...      -> {"sides":6,"count":3,"rolls":[4,3,4],"sum":11}
```

Значения `random`, `fact` и броски кубика меняются при каждом запросе — это нормально (используется модуль `random`).

### Вариант C — проверка граничных случаев (опционально)

Сервис возвращает ошибки валидации при некорректных параметрах:
```powershell
curl.exe -s "http://localhost:8050/api/random?min=10&max=5"   # -> HTTP 400, min больше max
curl.exe -s "http://localhost:8050/api/dice?sides=1"          # -> HTTP 422, sides должен быть >= 2
```
